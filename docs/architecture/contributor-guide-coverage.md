# Replacing procedural translation companions

Acceptance baseline: reusable translation explanations must be available in the version-matched OGP contributor guide, without requiring a language-specific procedural PDF. Sites retain local policy and delivery arrangements; teams retain language decisions. No consumer documentation or protected PDF is changed by this platform work.

The Kannada companion supplied the following useful categories. Its commands and historical capability claims are reference material, not current authority. The owning shared component is `OpenGuidePlatform.Agents.Integration`; exact operations remain owned by Core and the installed skills.

## Validation and limits

Require every linked shared page and asset to ship in GuideSite and retain valid local navigation. Run root platform acceptance, including package validation and sample workflows. Independently walk both assistant and manual routes against Core contracts and inspect the novice review handoff. The review sheet is a human aid, not an import schema, permission mechanism or replacement for candidate checks.

For purpose validation, a real newcomer should follow the first-translation path using only shared OGP guidance plus local policy/decision notes. Record where they need an explanation from the old companion or another person; move reusable missing explanations into OGP. Technical checks and an agent role-play do not establish beginner usability. Completion of such a real-user study must be recorded before claiming this purpose verified.

Publication/adoption is separate from implementation: these sources must be released and the consumer must adopt the matching package or link to that revision before its contributors receive them. A clean local build does not make the old companion obsolete for an unchanged consumer installation. Do not delete its language decisions or promise that site-specific work has been completed by this platform change.
